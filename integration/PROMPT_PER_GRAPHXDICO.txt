COLLEGARE GRAPHXDICO AL SIMULATORE MARIO

Pagina che simula Mario: https://mario.meralab.it/
Pagina del vero GraphXDico: https://graphxdico.it/ (sostituisci con l’URL preciso del tuo editor)
Origine Mario da configurare in GraphXDico: https://mario.meralab.it

Il tuo editor esiste già: aggiungi il collegamento a questo ricevitore online, senza dipendere da un Mario installato sul PC.

L'utente apre mario.meralab.it e clicca «Apri GraphXDico». Si apre la tua pagina con ?session=ID#token=TOKEN. Il simulatore resta in attesa. Nella demo l’URL del tuo editor si può cambiare nel campo «Indirizzo di GraphXDico», senza modificare file o rifare deploy. Comunica l’URL HTTPS esatto, inclusa l’eventuale sottopagina; deve essere l’origine finale, senza redirect verso un altro dominio.

Usa il file allegato grafxdico-mario-client.mjs: gestisce richiesta, invio e conferma. Configuralo con:
  marioOrigin: 'https://mario.meralab.it'
  originiConsentite: ['https://mario.meralab.it']

Le operazioni sono:
  const mario = creaClientMario({ marioOrigin, originiConsentite });
  const richiesta = await mario.leggiRichiesta();
  const pacchetto = await mario.prepara(richiesta, { disegni, tabelle });
  await mario.invia(pacchetto, { chiudiDopoInvio: true });

Importa creaClientMario dal file allegato. Collega queste operazioni ai tuoi dati e al pulsante «Esporta verso Mario».

Invia SEMPRE insieme disegno e tabelle:
- disegni: [{ targetId, blob, caption }], con un Blob PNG o JPEG reale;
- tabelle: [{ targetId, rows }], con i valori JSON delle righe prodotti da GraphXDico.

targetId e colonne arrivano da richiesta.targets. Ogni riga usa le chiavi delle colonne richieste. I campi text accettano stringhe/null, i boolean true/false/null. Restituisci tutte le tabelle richieste, anche quelle non pertinenti con rows: []; almeno una deve contenere righe. Non serve uno ZIP: l'adapter invia manifest JSON e file immagine insieme.

Dopo la conferma del ricevitore, l'adapter notifica Mario e chiude la finestra. Se la chiusura è impedita mostra «Invio riuscito, puoi chiudere». Su errore conserva il lavoro; per riprovare lo stesso invio riusa pacchetto. La X non esporta. Per Annulla usa mario.annulla({ chiudiDopoAnnulla: true }). Non registrare token nei log o nello storage; dopo aver creato il client rimuovi #token dalla barra con history.replaceState.

Il simulatore mostrerà immagine, tabelle e JSON ricevuti. Se le tue colonne sono diverse, mandaci un JSON d'esempio con significato e tipi dei valori: concordiamo la mappatura prima di adattare Mario. Non considerare automaticamente accettate colonne aggiuntive.

La prova da fare insieme: apri il tuo editor DAL simulatore, prepara uno schema e una distinta, esporta PNG o JPEG e controlla che immagine e righe arrivino al simulatore. Prova anche Annulla.

Quando il Mario originale sarà online, useremo lo stesso protocollo e configureremo in GraphXDico la sua origine reale al posto di https://mario.meralab.it. In Mario configureremo il tuo URL editor. Faremo una prova finale sul documento reale: il simulatore verifica lo scambio, non il salvataggio e la stampa del prodotto completo.
